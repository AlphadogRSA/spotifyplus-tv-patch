# Spotify+ TV 1.3.0.1 Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans task-by-task.

**Goal:** One Spotify APK with embedded Hush, native settings and graphic EQ.

**Architecture:** A pinned shell-owned Hush helper survives Spotify force-stop. The current process commits recovery state; the new process resumes its own session. Native profile settings host the restricted controls. The target EQ curve maps to actual output bands.

**Tech Stack:** Java 8/Android SDK 35, Python tooling, Kotlin/ReVanced, Playwright.

**Spec:** ../specs/2026-10-27-hush-tv-design.md

## Global Constraints
- One installed Spotify app, versionName 1.3.0.1, versionCode 2340200.
- Retain player-local mute, existing settings, lyrics and Spotify-only effects.
- Pinned upstream 4e9ded397338de5c69b1784c636feb3d34a8de01; GPL notices accompany helper code.
- No private key, account data or original client inputs in git.

## Review Focus
- Repeated ad signals and failure must not cause restart loops.
- The restart command must outlive the calling app process.
- A timer expiring during restart must prevent subsequent play commands.
- Settings rows must appear only in the real native settings host; native rows stay usable.
- Missing helper, dead media session and missing signing key must be reported accurately.
